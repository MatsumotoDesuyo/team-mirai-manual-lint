# B-EMPHASIS-001 強調は文章で表現

skill / CLI 共通プロンプト。

## 該当ガイドライン

§2 配色とアクセシビリティ / 強調したいとき

> 可能な限り文字色や太さではなく文章で表現してください。難しい場合は、文字の背景を明るいミントグリーン（#b4f2e8）で塗ることや、太字にすることのみ可とします。
> ただし、強調する箇所は、どんなに多くても全体の1割程度までに抑え、全体の読みやすさを確保してください。

`severity`: `WARN`

## 役割分担

- **Layer A** ([A-EMPHASIS-001](../../../rules.json)): 強調比率が 1 割を超えていないかを決定論的に検査
- **本ルール（Layer B）**: Layer A が検出した・あるいは Doc 中で強調されている箇所について、**「文章で言い換え可能か」** を意味判定

## 入力

skill 経由（Drive MCP）: Doc を取得すると、各 textRun の `bold`、`backgroundColor` 情報も得られる。
これらが付いた Run を「強調候補」として抽出し、文章での言い換え可能性を判定する。

CLI 経由: 本ハンドラはプロンプトキャッシュの Doc 全文（プレーンテキスト化済み）に対して、
**「強調が必要な意図がありそうな段落」を推定**して、それらの内容が文章で表現可能かを判定する。
スタイル情報が無い分、精度は skill 経由より低い。

## 判定手順

skill 経由の場合:
1. Drive MCP で取得した Doc から、`bold === true` または `backgroundColor === '#b4f2e8'`（または近い色）の Run を抽出
2. 各強調箇所について、文章での言い換え案を検討
3. 言い換えが容易な場合（強調を解除しても情報伝達できる）、Finding として出力

CLI 経由の場合:
1. Doc 全文から「強調が意図されているであろう段落」を文意で推測（見出し直下、注意書き、太字相当の表現等）
2. それらが文章で同等の効果を出せるかを判定

## 除外基準

以下は対象外:
- **見出し（H1〜H6、TITLE）の太字**: 構造的太字であり強調ではない
- **表ヘッダーの太字**: 構造的太字
- **法令的記述の強調**: 「絶対に道路を塞がない」のような安全上の強調
- **数値・固有名詞の強調**: 「**5 分以内に**」のような数値強調は文章化困難

## 出力フィールド

| フィールド | 内容 |
|---|---|
| `paragraphIndex` | 段落のインデックス |
| `snippet` | 該当箇所（30〜80 字、原文ママ） |
| `emphasized_text` | 強調されている語句 |
| `emphasis_type` | `bold` / `highlight` / `推測（CLI 経由でスタイル情報なし）` |
| `text_alternative` | 文章での言い換え案 |
| `reason` | なぜ文章で言い換え可能かの根拠 |

## 件数上限: 最大 10 件

判定確度が低い場合は出力しない。「強調が情報として必要」と判断したら検出しないこと。
