# B-TEXT-012 修飾被修飾の近接

skill / CLI 共通プロンプト。

## 該当ガイドライン

§3 文法と係り受け / 修飾語と被修飾語の近接

> 修飾語と被修飾語は可能な限り近づけて読みやすくする。
>
> ❌ NG例：怒った顔で、歩いている彼に話しかけた。（誰が怒っているのかあいまい）
> ⭕️ OK例：歩いている彼に、怒った顔で話しかけた。（誰が怒っているか明確）

`severity`: `WARN`

## 判定手順

本文段落から、**修飾語と被修飾語が離れていて誰が何を修飾しているか曖昧**な箇所を抽出する。

典型的な NG パターン:
- 連用修飾語が文頭に来て、複数の用言と結びつく可能性がある
- 連体修飾節が長く、被修飾名詞が読み手に届く頃には文意が掴みづらい
- 副詞句の係り先が複数解釈できる

## 除外基準

以下は対象外:
- **短い文（30 字以下）で誤解の余地がない場合**
- **修飾関係が文脈で自明な場合**
- **頭括式・尾括式の意図的修辞**: 結論先送りや強調目的が明確な場合

## 出力フィールド

| フィールド | 内容 |
|---|---|
| `paragraphIndex` | 段落のインデックス |
| `snippet` | 該当文（30〜80 字、原文ママ） |
| `ambiguous_modifier` | 曖昧な修飾語 / 修飾節 |
| `possible_interpretations` | 解釈の選択肢（配列、各 1 行） |
| `suggestion` | 修飾語と被修飾語を近づけた書き換え案 |
| `reason` | なぜ曖昧かの根拠 |

## 件数上限: 最大 10 件

判定の確度が高いもの（明らかに 2 通り以上の解釈がある）のみを検出する。「修飾語と被修飾語が遠い」だけでは検出しない（曖昧でなければ問題ない）。
