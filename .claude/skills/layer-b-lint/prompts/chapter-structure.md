# B-STRUCT-001 全体の構成（前編後編・章立て）

skill / CLI 共通プロンプト。

## 該当ガイドライン

§3 全体の構成

> 誰もが長文を読む必要がないように、必須内容だけを記載した前編、上級者向けの後編に分けて表現します。
>
> - 前編: 初心者向けの内容で 2 ページ分で A4 で印刷できる。流れは概要、やること（準備、活動）、注意点
> - 後編: 経験者用でより効果的な活動のコツや、法令に解説を記載します。
> - ただし、全体が短い場合は前編・後編に分ける必要はありません

`severity`: `WARN`

## 判定手順

Doc 全体の見出し構造を確認し、以下のいずれかに該当する場合に Finding を出す。

### 1. 全体が長いのに前編・後編に分かれていない

- 本文段落数が約 50 段落以上、または文字数が約 5000 字以上にも関わらず、
- 「前編」「後編」または「初心者向け」「経験者向け」「上級編」のような上位区分の見出しが存在しない

### 2. 前編の流れが「概要 → 準備 → 活動 → 注意点」になっていない

- 前編が存在する場合、その下位見出しの順序を検証
- 順序の入れ替わり、抜け落ちがある場合

### 3. 法令・コツの記述が前編に集中しすぎている

- 「公職選挙法」「道路交通法」「コツ」「ポイント」のような後編相当の内容が前編に大量にある

## 除外基準

以下は対象外:
- **明らかに短い Doc**（30 段落以下 or 3000 字以下）: 前編・後編分割不要
- **テンプレート Doc / 設計書 / 議事録**: マニュアル以外の用途で本ルールは適用外
- **後編に相当する別 Doc がリンクで参照されている場合**

## 重要

本ルールは「**Doc 全体の構造判定**」なので、Finding は通常 **最大 1〜2 件**で出る（個別段落の問題ではなく、全体の構成問題）。

## 出力フィールド

| フィールド | 内容 |
|---|---|
| `paragraphIndex` | 構成問題の起点となる段落（通常は Doc 冒頭付近を指す。または -1 で「Doc 全体」） |
| `snippet` | 構成問題を示す代表的箇所（30〜80 字） |
| `structure_issue` | 問題類型: `前後編未分割` / `前編順序` / `内容偏在` |
| `current_structure` | 現状の見出し構造のサマリ（数行） |
| `suggestion` | 推奨される構造 |
| `reason` | 判定根拠 |

## 件数上限: 最大 3 件

通常は 0〜1 件で済む。多くても 3 件まで。
