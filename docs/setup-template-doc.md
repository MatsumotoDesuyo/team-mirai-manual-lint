# テンプレート Doc 作成手順（ミッションオーナー用）

このドキュメントは、team-mirai-manual-lint の **配布用テンプレート Google Doc** を Drive 上に作成する手順を示します。サポーターはこのテンプレート Doc を「コピーを作成」するだけで、自分のマニュアル Doc に Layer A チェッカーが組み込まれた状態になります。

> **対象読者**: テンプレート Doc を公開する人（個人サポーター名義での公開者）。一般のサポーターはこの手順を実行する必要はありません。

## 設計上の重要事項

Apps Script のサービス設定（**Advanced Docs Service**）は、Doc を「コピーを作成」したとき **コピー先に一緒に持っていかれます**。

つまり、テンプレート側で 1 回だけ設定すれば、コピーしたサポーターは追加作業不要です。サポーターは **初回の OAuth 権限承認だけ** で実行できます。

これにより、サポーター側の手順は最小化されます。テンプレート側を丁寧に作るのがミッションオーナーの責務です。

---

## 手順

### 1. Drive で空 Doc を作成

1. [Google Drive](https://drive.google.com/) を開く
2. 「新規 → Google ドキュメント → 空白のドキュメント」
3. ドキュメント名を設定（推奨: `[テンプレート] チームみらいマニュアル lint チェッカー入り`）

### 2. Apps Script エディタを開く

1. Doc のメニュー「拡張機能 → Apps Script」をクリック
2. 新しいタブで Apps Script エディタが開く
3. デフォルトの `Code.gs` が表示される

### 3. loader.gs を貼り付け

1. `Code.gs` の既存内容（`function myFunction() {…}` 等）を**全消去**
2. 以下の URL から最新の loader.gs を取得して全文を貼り付け:
   
   <https://raw.githubusercontent.com/MatsumotoDesuyo/team-mirai-manual-lint/main/gas/loader.gs>

3. 左上のプロジェクト名「無題のプロジェクト」をクリックして名前を変更（推奨: `team-mirai-manual-lint-loader`）

### 4. Advanced Docs Service を有効化

これが **テンプレートの肝** です。

1. Apps Script エディタの**左サイドバー「サービス」**（鎖アイコン）をクリック
2. 「サービスを追加」ダイアログから **「Google Docs API」** を選択
3. 識別子は `Docs` のまま（変更しない）
4. 「追加」をクリック
5. 左サイドバーに `Docs (Google Docs API ...)` が追加されたことを確認

> **未実施だと**: `Docs is not defined` エラーで Layer A の見出しスタイル系・色系・表系ルール（合計 14 ルール）がすべて雛形 INFO 状態になります。必ず実施してください。

### 5. 保存

`Ctrl+S`（または 💾 アイコン）で保存します。

### 6. Doc 側で動作確認

1. Doc のタブに戻る
2. ブラウザを **再読込（F5）** — これで `onOpen` が走り、メニューバーに「**マニュアルチェック**」が追加される
3. メニューが追加されたことを確認

メニューが出ない場合は [トラブルシュート](troubleshooting.md) を参照。

### 7. 動作テスト（任意・推奨）

テンプレート公開前に、自分自身でテストすることを推奨:

1. テンプレート Doc に適当な本文を 2〜3 段落書く
2. 「マニュアルチェック → チェック実行」
3. 初回の権限承認画面で「許可」（自分のアカウントなので安全）
4. サイドバーが右側に開き、Layer A の Finding が表示されることを確認
5. 確認後、本文を全削除して空テンプレートに戻す

> **重要**: 本文に書いたテスト内容や、テスト実行で末尾レポートが書き込まれていないこと（既定 OFF）を確認してください。万一末尾にレポートが残っている場合は手動削除。

### 8. 共有設定

1. Doc 右上の「共有」ボタン
2. 「全般アクセス」を **「リンクを知っている全員」「閲覧者」** に変更
3. 「リンクをコピー」ボタンで URL 取得

> **編集者にしない**: 「閲覧者」のままで OK。サポーターは「コピーを作成」するので、テンプレート本体を編集する権限は不要です。むしろ「編集者」にすると誤って共有テンプレートを上書きする事故が起き得ます。

### 9. README へのリンク反映

1. リポジトリの [README.md](../README.md) を開く
2. **「サポーター向け Quick Start」セクションの `<TEMPLATE_DOC_URL>` プレースホルダー** を、取得したリンクで置換
3. 同様に **`<TEMPLATE_DOC_COPY_URL>` プレースホルダー** を、`https://docs.google.com/document/d/<DOC_ID>/copy` 形式で置換（コピー直接リンク）
4. コミット & プッシュ:
   ```bash
   git add README.md
   git commit -m "配布: テンプレート Doc URL を反映"
   git push origin main
   ```

### 10. 告知

Slack / オプチャ等でサポーターに配布告知します。README の Quick Start を案内するだけで十分です。

## 更新が必要なとき

loader.gs のロジック自体に変更がある場合（例: 新しいスコープが必要になった、サービス追加が必要になった等）、テンプレート Doc 側を更新する必要があります。

- 軽微なロジック変更（リモート配信される `.gs` ファイルや HTML テンプレート、`rules.json` の変更）は **テンプレート更新不要**。サポーター側で次回実行時に自動取得されます
- loader.gs 本体の変更が必要な場合のみ、本手順の Step 3 を再実行し、Code.gs を再貼り付け

判断に迷ったら、[トラブルシュート](troubleshooting.md) の「loader.gs を再貼り付けすべきタイミング」を参照してください。
